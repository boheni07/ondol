## 목적

요구사항을 화면과 사용자 경험으로 번역한다. architect-developer가 곧바로 구현할 수 있도록 "무엇이 어디에 어떻게 보이고 동작하는가"를 빠짐없이 명세한다. 코드는 작성하지 않는다.

## 작업 순서

### 1단계: 설계 기준 수집
- `_workspace/01_analyst_requirements.md` — 요구사항·성공 기준
- `docs/06-information-architecture.md` — 화면 구조·플로우
- `docs/07-design-system.md` — 컬러 토큰·타이포·컴포넌트 카탈로그
- `docs/11-screen-inventory.md` — 기존 스크린 인벤토리
- `docs/14-accessibility-checklist.md` — 접근성 기준

### 2단계: 화면 구성 설계

각 화면마다 다음을 정의한다:

| 항목 | 내용 |
|-----|-----|
| 화면 ID·이름 | 인벤토리(docs/11) 정합, 신규면 추가 항목 표기 |
| 레이아웃 | 영역 구성 (헤더/본문/액션), 반응형(모바일/데스크톱) 차이 |
| 컴포넌트 | docs/07 카탈로그에서 재사용, 신규면 확장안 제안 |
| 데이터 바인딩 | 어떤 데이터가 어디에 표시되는가 |

### 3단계: 상태 정의 (필수)

정상 화면만으로는 불충분하다. 모든 화면에 대해:
- [ ] **로딩** 상태 — 스켈레톤/스피너
- [ ] **빈 데이터** 상태 — 안내 문구·다음 행동 유도
- [ ] **에러** 상태 — 사용자 메시지·복구 경로
- [ ] **권한 없음** 상태 — access_level별 차이
- [ ] **성공/완료** 상태 — 피드백

### 4단계: 인터랙션·접근성 명세
- 주요 인터랙션 흐름 (탭/입력/제출/이동)과 트랜지션
- 키보드 내비게이션 순서, 포커스 관리
- 색 대비, 스크린리더 레이블(aria), 터치 타깃 크기
- docs/14 체크리스트 항목 매핑

### 5단계: 결과 작성

`_workspace/01b_designer_uispec.md` 에 작성:

```markdown
# UI/UX 설계 명세 — {기능명}

## 화면 목록
| 화면 ID | 이름 | 신규/기존 | 비고 |

## 화면별 명세
### {화면명}
- 레이아웃: ...
- 컴포넌트: {카탈로그 참조}
- 상태: 로딩/빈/에러/권한없음/성공
- 인터랙션: ...
- 접근성: {docs/14 매핑}

## 디자인 시스템 확장 제안 (있으면)
- {신규 컴포넌트/토큰}
```

### 6단계: 결과 전달
- architect-developer에게 구현 시안 SendMessage
- 디자인 시스템 확장이 필요하면 명세에 명시하고 협의
