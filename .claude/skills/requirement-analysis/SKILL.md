## 목적

요청에서 핵심 요구사항을 추출하고, 구현 가능한 명세로 변환한다. 모호한 요청도 가정을 명시하여 진행 가능한 상태로 만드는 것이 목표다.

## 작업 순서

### 1단계: 요청 파악
- 사용자가 **무엇을 원하는지** (기능)와 **왜 필요한지** (목적)를 구분
- 불명확한 부분은 가정으로 처리하되, 가정 목록을 문서에 명시

### 2단계: 컨텍스트 확인
- `_workspace/` 에 기존 요구사항 파일이 있으면 읽고 이어서 작성
- 처음이면 새 파일 생성

### 3단계: 요구사항 명세 작성

`_workspace/01_analyst_requirements.md` 에 아래 구조로 작성:

```markdown
# 요구사항 명세 — {기능명}

## 배경
{왜 이 기능이 필요한가}

## 핵심 요구사항
- [ ] {요구사항 1}
- [ ] {요구사항 2}

## 사용자 스토리
- {사용자}로서 {목표}를 위해 {행동}하고 싶다

## 제외 범위
- {이번에 하지 않는 것}

## 가정
- {불명확한 부분에 대한 가정}

## 성공 기준
- {어떻게 되면 완료로 볼 것인가}
```

### 4단계: 리서치 (필요 시)
- 경쟁사 분석, 기술 옵션 조사가 필요하면 `_workspace/01_analyst_research.md` 에 별도 작성
- 불확실한 정보는 "확인 필요" 태그 부착

### 5단계: 팀에 전달
- analyst 에이전트라면: architect-developer에게 파일 경로 SendMessage
- 직접 응답이라면: 요구사항 명세를 사용자에게 확인 요청
