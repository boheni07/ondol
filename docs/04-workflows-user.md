## 1. 보호자

보호자는 플랫폼의 최고 관리자다. 당사자를 등록하고, 모든 기록에 접근하며, 다른 이해관계자에게 권한을 부여한다.

### 1-1. 보호자 최초 온보딩

```mermaid
flowchart TD
    A([앱/웹 접속]) --> B[회원가입 선택]
    B --> C[역할 선택: 보호자]
    C --> CC[본인 동의 수집\n필수: 약관·개인정보·위탁고지\n선택: 마케팅\nconsents INSERT subject_user_id\n→ docs/05 §1-3, 화면 A-08]
    CC --> D[이름·연락처·이메일 입력]
    D --> E[이메일 인증]
    E --> F{인증 성공?}
    F -- 아니오 --> E
    F -- 예 --> G[보호자 계정 생성 완료]
    G --> H[당사자 등록 시작]
    H --> I[당사자 기본 정보 입력\n이름·생년월일·성별]
    I --> CD[당사자 정보 대리동의\n동의 주체 판정 F1/F2/F3\non_behalf=true·consented_by=보호자\n→ docs/05 §1-3, 화면 G-03 위자드 동의 Step]
    CD --> J[장애 유형·정도 입력]
    J --> JS[민감정보 별도 동의\nsensitive_info\n장애·건강\n→ docs/05 §1-3]
    JS --> JU{고유식별정보\n입력 예정?\n장애등록번호·증명서번호}
    JU -- 예 --> JU1[고유식별정보 별도 동의\nunique_identifier\n→ docs/05 §1-3]
    JU -- 아니오 --> K
    JU1 --> K[응급 정보 입력\n알레르기·금기약·비상연락처]
    K --> L[프로필 사진 업로드\n선택]
    L --> M[당사자 등록 완료]
    M --> N{다른 당사자\n추가?}
    N -- 예 --> H
    N -- 아니오 --> O[대시보드 진입]
    O --> P{이해관계자\n초대할 사람 있음?}
    P -- 예 --> Q[권한 부여 워크플로우\n→ 1-3 참조]
    P -- 아니오 --> R[온보딩 완료\n기록 시작 가능]
```

### 1-2. 보호자 일상 사용 흐름

```mermaid
flowchart TD
    A([앱 로그인]) --> B[대시보드\n담당 당사자 목록]
    B --> C{오늘 할 작업\n선택}

    C --> D1[기록 입력]
    C --> D2[기록 조회]
    C --> D3[권한 관리]
    C --> D4[알림 확인]
    C --> D5[접근 로그 확인]

    %% 기록 입력 분기
    D1 --> E1{기록 분야 선택}
    E1 --> F1[A.의료 기록 입력\n→ 1-4 참조]
    E1 --> F2[C.복지 서류 등록]
    E1 --> F3[F.법적 서류 보관]
    E1 --> F4[기타 분야 기록]

    %% 기록 조회 분기
    D2 --> E2{조회 방식}
    E2 --> G1[생애주기 타임라인 전체 보기]
    E2 --> G2[분야별 필터 조회]
    E2 --> G3[날짜 범위 검색]
    E2 --> G4[이해관계자별 필터]

    %% 권한 관리
    D3 --> H1[권한 부여 → 1-3 참조]

    %% 접근 로그
    D5 --> I1[당사자별 접근 로그 조회]
    I1 --> I2{의심 접근\n발견?}
    I2 -- 예 --> I3[해당 이해관계자\n권한 회수]
    I2 -- 아니오 --> I4[확인 완료]
```

### 1-3. 이해관계자 권한 부여/회수

```mermaid
flowchart TD
    A([권한 관리 메뉴]) --> B[이해관계자 목록 조회]
    B --> C{작업 선택}

    C --> D1[신규 권한 부여]
    C --> D2[기존 권한 수정]
    C --> D3[권한 회수]

    %% 신규 권한 부여
    D1 --> E1{이해관계자\n계정 있음?}
    E1 -- 있음 --> F1[이메일/이름으로 검색]
    E1 -- 없음 --> F2[초대 링크 발송\n이메일 입력]
    F2 --> F3[초대 수락 대기]
    F3 --> F4{수락?}
    F4 -- 아니오 --> F5[재발송 또는 취소]
    F4 -- 예 --> F1
    F1 --> G1[대상자 확인]
    G1 --> H1[분야 선택\n의료/교육/복지/일상/전환/법적]
    H1 --> H2[접근 수준 선택\n열람/작성/편집]
    H2 --> H3[유효 기간 설정\n시작일~종료일]
    H3 --> H4[권한 부여 사유 입력\n선택]
    H4 --> H5[미리보기 확인]
    H5 --> H6{최종 확인}
    H6 -- 취소 --> H1
    H6 -- 확인 --> H7[권한 저장\nDB: permissions INSERT]
    H7 --> H8[permission_logs 기록]
    H8 --> H9[이해관계자에게 알림 발송]
    H9 --> H10[완료]

    %% 권한 회수
    D3 --> I1[회수할 이해관계자 선택]
    I1 --> I2[회수할 분야/권한 선택]
    I2 --> I3{확인}
    I3 -- 취소 --> B
    I3 -- 확인 --> I4[permissions.is_active = false]
    I4 --> I5[permission_logs 기록\naction: revoked]
    I5 --> I6[대상자에게 알림 발송]
    I6 --> I7[완료]
```

```mermaid
    %% 진단 요약

    D1 --> D2[진단명·KCD코드 입력]
```

## 2. 당사자

당사자는 이미지 선택 방식의 전용 UI를 통해 자기표현을 기록하고, 다른 이해관계자의 기록을 열람한다.

### 2-1. 당사자 계정 최초 접속

```mermaid
flowchart TD
    A([보호자가 당사자 계정 생성]) --> B[당사자 이름으로 person_accounts 생성]
    B --> C[초대 링크/코드 발송\n당사자 또는 보조자에게]
    C --> D([당사자 앱 접속])
    D --> E[초대 코드 입력 또는 링크 클릭]
    E --> F[비밀번호 설정\n간단한 PIN 또는 생체인증]
    F --> FC{동의 주체 판정\n→ docs/05 §1-3}
    FC -- 성인 본인 --> FC1[본인 동의 수집\nsubject_user_id=당사자 계정\non_behalf=false]
    FC -- 미성년·피후견 --> FC2[법정대리인 대리동의 기록\non_behalf=true\n→ 보호자 온보딩 1-1에서 수집]
    FC1 --> G[접근성 설정\n아이콘 크기·색상·언어 수준]
    FC2 --> G
    G --> H{설정 확인}
    H --> I[당사자 전용 홈 화면 진입]
    I --> J[튜토리얼\n아이콘 사용법 안내 3단계]
    J --> K[온보딩 완료]
```

## 3. 활동지원사

활동지원사는 서비스 제공일마다 모바일로 활동지원 일지를 작성한다. 담당 기간과 일상 분야 기록에만 접근한다.

### 3-1. 활동지원사 온보딩

```mermaid
flowchart TD
    A([보호자가 초대 링크 발송]) --> B([활동지원사 앱 설치])
    B --> C[초대 링크 클릭]
    C --> D{기존 계정\n있음?}
    D -- 있음 --> E[로그인]
    D -- 없음 --> F[회원가입\n이름·연락처·소속기관]
    F --> FC[본인 동의 수집\n약관·개인정보 필수·위탁고지\nconsents INSERT subject_user_id\non_behalf=false\n→ docs/05 §1-3, 화면 A-08]
    FC --> G[이메일 인증]
    G --> E
    E --> H[당사자 연결 요청 확인\n이름·보호자 확인]
    H --> I{수락?}
    I -- 아니오 --> J[거절 처리\n보호자에게 알림]
    I -- 예 --> K[권한 확인\n일상 분야 Write + 기간]
    K --> L[담당 당사자 대시보드 진입]
    L --> M[온보딩 투어\n일지 작성 방법 안내]
    M --> N{이전 기록\n열람 필요?}
    N -- 예 --> O[인수인계 기록 확인\nhandovers 조회]
    N -- 아니오 --> P[준비 완료]
```

### 3-2. 활동지원 일지 작성 (DAI-002)

```mermaid
flowchart TD
    A([서비스 시작]) --> B[앱 열기\n당사자 선택]
    B --> C{오늘 권한\n유효?}
    C -- 아니오 --> D[접근 불가 안내\n보호자에게 연락 안내]
    C -- 예 --> E[새 일지 작성]

    E --> F[서비스 날짜 확인\n자동: 오늘]
    F --> G[서비스 시작 시간 입력]
    G --> H[활동 카테고리 선택\n이동지원/가사지원/외출지원 등]
    H --> I[활동 상세 내용 입력]
    I --> J[소요 시간 입력]
    J --> K{활동 추가?}
    K -- 예 --> H
    K -- 아니오 --> L[식사 체크\n아침/점심/저녁]
    L --> M[건강 상태 선택\n양호/감기/피로/통증]
    M --> N{특이 행동\n있었나요?}
    N -- 예 --> O[행동 관찰 기록\n선택 또는 텍스트]
    N -- 아니오 --> P
    O --> P{사고/특이사항\n있었나요?}
    P -- 예 --> Q[사고 내용 기록\n필수 상세 기입]
    P -- 아니오 --> R
    Q --> R[다음 날 인계 사항 입력\n선택]
    R --> S[서비스 종료 시간 입력]
    S --> T[실 서비스 시간 자동 계산]
    T --> U{임시저장 또는\n최종 제출?}
    U -- 임시저장 --> V[is_draft=true 저장]
    V --> W[나중에 계속 작성 가능]
    U -- 최종 제출 --> X[records INSERT\ndomain:daily, type:DAI-002]
    X --> Y[access_logs 기록]
    Y --> Z[보호자에게 알림 발송]
    Z --> AA[제출 완료]
```

### 3-3. 이전 기록 및 인수인계 확인

```mermaid
flowchart TD
    A([이전 기록 확인 메뉴]) --> B{확인 목적}
```
