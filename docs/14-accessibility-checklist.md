# 접근성 체크리스트 (WCAG 2.1) — OnDol 플랫폼

> 버전: v1.0 | 작성일: 2026-06-14

OnDol은 일반 화면에서 **WCAG 2.1 AA(대비 4.5:1)**를, 당사자 접근성 모드(`ui_mode: 'icon'`)에서 **AAA(대비 7:1, 터치 타깃 56px)**를 목표로 한다. 본 체크리스트는 인식·운용·이해·견고 4원칙 + 당사자 모드 전용 강화 기준 + 검증 도구로 구성된다.

> 표기: `- [ ] 항목 — 기준/수치 — 검증 방법 — 근거(docs 위치)`
> 근거 약어: DS=07-design-system.md, IA=06-information-architecture.md, WBS=08-wbs.md

---

## 1. 인식 (Perceivable)

### 1-1. 컬러 대비

- [ ] 본문 텍스트 대비 — 일반 화면 **4.5:1 이상**(AA) — axe/Lighthouse 대비 검사 + 수동 샘플링 — DS §1 헤더(AA 기준), DS §9-2(4.5:1 AA), WBS 17.3.3
- [ ] 당사자 모드 텍스트 대비 — **7:1 이상**(AAA) — 대비 측정기로 토큰별 검증 — DS §9-2(7:1 AAA), DS §1-1 헤더
- [ ] 도메인 색상(6분야) bg+text 조합 대비 — **7:1 이상**(AAA) — 6개 도메인 토큰 각각 측정(medical/education/welfare/daily/transition/legal) — DS §1-4(7:1 이상 명시)
- [ ] 고대비 모드 메인 텍스트 — 배경 `#FFFFFF` + 텍스트 `#000000` — 토큰 적용 확인 — DS §9-3(당사자 전용 컬러 고대비)
- [ ] 고대비 모드 warm 버튼 — `#C4500A`(기본 `#E8724A`보다 어둡게) — 색상 토큰 검증 — DS §9-3
- [ ] 상태/의미 전달 — 색상 단독 의존 금지(아이콘·텍스트 병행) — StatusBadge·DomainBadge 시각 검토 — DS §8-4(Badge 아이콘+텍스트)

### 1-2. 텍스트 크기 · 확대

- [ ] 기본 본문 크기 — body-md **16px**(Base) — 렌더링 측정 — DS §2-2(body-md 16px Base)
- [ ] 당사자 모드 본문 확대 — body-md(16px) → body-lg **20px**(`text-xl`) — 모드 전환 후 측정 — DS §9-1(타이포 오버라이드)
- [ ] 당사자 모드 보조/캡션 확대 — body-sm 14→16px, caption 12→14px — 모드 전환 후 측정 — DS §9-1
- [ ] 사용자 글자 크기 설정 — 접근성 설정에서 글씨 크기 조절(font_scale) — P-21 접근성 설정 동작 확인 — IA §5-2 Tab3(글자 크기), WBS 14.7·3.4.3
- [ ] 200% 브라우저 확대 — 가로 스크롤·콘텐츠 잘림 없음 — 브라우저 줌 200% 수동 테스트 — DS §2-2(반응형 스케일)
- [ ] 줄 간격 가독성 — line-height 본문 24px 이상(body-md 16/24) — 타이포 토큰 검증 — DS §2-2

### 1-3. 대체 텍스트 · ARIA

- [ ] icon-only 버튼 — `aria-label` 필수(예: 닫기 버튼) — axe + 스크린리더 라벨 읽기 — DS §8-1(`<Button iconOnly aria-label="닫기">`)
- [ ] 도메인 아이콘/뱃지 — 의미 텍스트 또는 aria-label 병기 — 스크린리더 검증 — DS §6-2, §8-4
- [ ] 자기표현 이모지 아이콘 — 각 아이콘 텍스트 라벨(예: "건강해요") 동반 — ST-08 카드 라벨 확인 — DS §9-4(아이콘+라벨), DS §6-3
- [ ] 이미지/사진 첨부 — 대체 텍스트 또는 설명 제공 — 스크린리더 검증 — DS §8-6(RecordCard 첨부)
- [ ] ARIA 레이블 전반 — 스크린리더 호환 ARIA 적용 — axe + NVDA/VoiceOver — WBS 17.3.2, DS §9-5

## 2. 운용 (Operable)

### 2-1. 키보드 네비게이션

- [ ] 전 인터랙티브 요소 Tab 접근 — 모든 버튼·입력·카드 Tab 도달 가능 — 키보드만으로 전체 순회 — DS §9-5(모든 인터랙티브 Tab 접근), WBS 17.3.1
- [ ] 버튼/카드 활성화 — Enter·Space로 동작 — 키보드 조작 테스트 — DS §9-5
- [ ] 모달/시트 닫기 — Escape로 닫힘 — 키보드 테스트 — DS §9-5
- [ ] 포커스 트랩 — 모달·Bottom Sheet 내 포커스 가둠 + 닫을 때 복귀 — 키보드 순회 검증 — DS §8-7 Modal, §8-8 Bottom Sheet
- [ ] 키보드 네비게이션 전반 — WCAG 2.1 AA 키보드 운용 — Playwright 키보드 시나리오 — WBS 17.3.1

### 2-2. 포커스 순서 · 표시

- [ ] 포커스 표시(일반) — outline **2px solid** primary-500, offset 2px — 시각 확인 — DS §8-1 States(Focus 2px primary-500), DS §9-5(2px solid)
- [ ] 포커스 표시(당사자 AAA) — **3px solid `#000000`** — 고대비 모드 포커스 확인 — DS §9-3(포커스 링 #000 3px), DS §9-5(AAA 3px)
- [ ] 입력 필드 포커스 — 테두리 primary-500 2px — Input 상태 확인 — DS §8-2 Input States(Focus 2px)
- [ ] 논리적 포커스 순서 — DOM/시각 순서 일치, 위자드 단계 흐름 유지 — 키보드 순회 — IA §6 플로우 Step, DS §8-13 Multi-step
- [ ] Step Indicator 이동 — 단계 점/탭 키보드·포커스 접근 — Step 컴포넌트 검증 — DS §8-10, IA Flow-1(상단 점 터치 이동)

### 2-3. 터치 타깃

- [ ] 터치 타깃(일반) — 최소 **44×44px** — 모바일 요소 측정 — DS §6-1(모바일 터치 영역 최소 44×44px), DS §9-2(Tap target 44×44px)
- [ ] 터치 타깃(당사자 모드) — **56×56px** — 접근성 모드 측정 — DS §9-2(Tap target 56×56px), DS §9-5(스위치 접근 56×56px)
- [ ] 버튼 높이(당사자) — 기본 40px → **56px**(xl size) — 모드 전환 측정 — DS §9-2(Button height 56px), DS §8-1 Sizes(xl 56px 당사자 전용)
- [ ] 하단 탭바 높이 — 56px + Safe Area Inset — 모바일 렌더 확인 — DS §3-2(하단 탭바 56px), DS §8-17
- [ ] 중앙 FAB 크기 — 56×56px rounded-full — 모바일 확인 — DS §8-17(FAB 56×56px)

### 2-4. 모션 감소

- [ ] prefers-reduced-motion 대응 — 애니메이션/트랜지션 0.01ms로 비활성 — OS 설정 후 동작 확인 — DS §7-4(Reduced Motion CSS)
- [ ] 완료 애니메이션 — 모션 감소 시 즉시 표시(자기표현 완료 등) — P-03 화면 검증 — DS §7-3, IA Flow-1 완료, WBS 14.3
- [ ] 자동 사라짐 토스트 — 3초 자동 + 수동 X 닫기 병행 — Toast 동작 확인 — DS §8-9(Toast 3초/X 닫기)

## 3. 이해 (Understandable)

### 3-1. 쉬운 언어 (당사자 모드)

- [ ] 당사자 기록 요약 — 쉬운 언어 summary 필드, 큰 글씨 제공 — P-11 기록 상세 검증 — IA §5-2 Tab2(쉬운 언어·큰 글씨), WBS 14.5·16.3.4(쉬운 요약)
- [ ] 1화면 1질문(자기표현) — 각 스텝 1질문, 단순 선택 — Flow-1 검증 — IA Flow-1(1화면=1질문)
- [ ] 아이콘+텍스트 병행 표현 — 감정/활동/식사/몸상태 아이콘에 한글 라벨 — ST-08 검증 — DS §6-3, §9-4

### 3-2. 일관된 내비게이션

- [ ] 사이드바/탭바 일관성 — 역할별 고정 위치·순서 유지 — 화면 간 일관성 검토 — IA §4 사이드바·§5 탭 구조
- [ ] 활성 상태 표시 일관 — 활성 메뉴 primary-100 bg + left 3px border — Sidebar/TabBar 확인 — DS §8-16 Sidebar, §8-17 TabBar
- [ ] 브레드크럼/네비 — Depth 3+ 자동 브레드크럼, NavBar 뒤로가기 — IA 패턴 검토 — IA §2-1(Breadcrumb), §2-2(NavBar)

### 3-3. 입력 오류 안내

- [ ] 오류 메시지 표시 — ErrorMessage(body-sm, error-text) 필드 하단 — 폼 오류 검증 — DS §8-2(ErrorMessage 유효성 실패 시)
- [ ] 오류 필드 시각 표시 — 테두리 error-accent 2px(색상+테두리) — Input Error 상태 확인 — DS §8-2 Input States(Error)
- [ ] InlineAlert 안내 — success/warning/error/info + 아이콘 + 설명 — 알림 컴포넌트 검증 — DS §8-9(InlineAlert)
- [ ] 필수 항목 안내 — 위자드 필수 입력 표시(예: ✅ 필수) — Flow-2/3 검증 — IA Flow-2(필수 표기), §6 플로우

## 5. 당사자 모드 전용 강화 기준

> `ui_mode: 'icon'` 활성 시 자동 적용. WCAG 2.1 **AAA** 목표. (근거: DS §9, IA §5-2·Flow-1)

- [ ] 아이콘 우선 UI — 텍스트보다 아이콘 우선, 단순 레이아웃 — P-01/P-02 검증 — DS §9 헤더, IA §5-2(아이콘 크게)
- [ ] 자기표현 아이콘 크기 — **72×72px** 커스텀 일러스트 — ST-08 카드 측정 — DS §6-3(72×72px), DS §9-4, IA Flow-1(72×72px)
- [ ] 아이콘 선택 카드 너비/높이 — 화면 45%(2열), 높이 120px → 접근성 **140px** — IconSelectorCard 측정 — DS §9-4(카드 높이 140px)
- [ ] 큰 CTA 버튼 — 당사자 홈 대형 "오늘 기록하기" CTA — P-01 측정 — DS §9 헤더, IA §5-2 Tab1(대형 CTA), WBS 14.1·16.3.1(큰 CTA)
- [ ] 일반 아이콘 크기 확대 — 20px → **28px**(접근성 모드) — 모드 전환 측정 — DS §9-2(Icon size 28px)
- [ ] 카드 패딩 확대 — p-4 → **p-6** — 모드 전환 확인 — DS §9-2(Card padding p-6)
- [ ] 보더 반경 확대 — radius-lg → radius-2xl(20px) — 모드 확인 — DS §9-2, DS §5(radius-2xl 20px 당사자 아이콘 카드)
- [ ] 큰 체크박스 — CheckboxLg **24×24px**(접근성 모드) — 컴포넌트 확인 — DS §8-3(CheckboxLg 24×24px 접근성 모드)
- [ ] 버튼 텍스트 확대 — button-md → button-lg(16px font-semibold) — 모드 측정 — DS §9-1
- [ ] 스위치 접근(Switch Access) — 터치 영역 최소 56×56px — 보조기기 시뮬레이션 — DS §9-5
- [ ] 탭 단순화 — 당사자 탭 2~3개로 축소 — 모바일 탭바 확인 — IA §5-2(탭 2~3개 단순화)
- [ ] 진행 표시 단순화 — 4칸 점 인디케이터(●●○○) — Flow-1 검증 — IA Flow-1(Progress Bar 점), DS §8-10
